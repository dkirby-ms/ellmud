## Spawn Context

Two-part local dev auth bypass: (1) `AUTH_REQUIRED` defaulted to `false` in server config, bypassing all room-level auth checks. (2) Client `useDevAutoLogin` hook silently authenticated dev users in local environments, masking real login flows.

## Work Completed

### Part 1: Server Config Default
- Flipped `AUTH_REQUIRED` default from `false` → `true` in `packages/server/src/config.ts`
- Colyseus rooms now require valid auth tokens unless explicitly configured otherwise
- Integration tests call `initColyseusAuth()` directly and do not depend on config default

### Part 2: Client Auto-Login Opt-In
- Converted `useDevAutoLogin` to opt-in via `VITE_DEV_AUTO_LOGIN=true` environment variable
- Developers now see the login form by default in local dev
- Developers can restore old behavior by setting `VITE_DEV_AUTO_LOGIN=true` in `packages/client/.env`

### Documentation
- Updated `.env.example` with `VITE_DEV_AUTO_LOGIN` and clarified `AUTH_REQUIRED` behavior
- Added inline comments in `packages/client/src/pages/Login.tsx`

## Impact Assessment

- **Team:** All local dev workflows now require login. Register through login form or opt-in to auto-login via environment variable.
- **Tests:** No impact. All 1,677 tests pass. Tests use `initColyseusAuth()` directly.
- **CI/CD:** No impact. Production already had auth configured via environment variables.
- **Security:** Local dev now matches deployment behavior more closely, surfacing auth bugs before production.
