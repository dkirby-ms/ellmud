## Summary

Diagnosed 6 issues preventing Entra OAuth from functioning in local dev and UAT environments. Issues span configuration, code bugs, deployment gaps, and operational lockout risk. All issues are fixable within current sprint.

## Issues Found

### Critical Bugs (blocking functionality)

1. **Server doesn't load `.env`** — No `dotenv` import, no `--env-file` flag. Server never sees `ENTRA_*` environment variables in local dev.
   - Impact: All Entra config appears undefined

2. **Redirect URI path mismatch** — `.env.example` has `ENTRA_REDIRECT_URI=http://localhost:3000/auth/callback`, server route is `/auth/entra/callback`.
   - Impact: OAuth authorization code never exchanged, Express catch-all serves `index.html`

3. **openid-client v6 API misuse** — `redirectUri` passed as 3rd argument to `discovery()` where it's interpreted as `client_secret`.
   - Impact: Discovery fails or succeeds with wrong secret configured

4. **CIAM issuer URL uses GUID as subdomain** — Current code: `https://${tenantId}.ciamlogin.com/...` where `tenantId` is the GUID.
   - Impact: DNS resolution fails, OIDC discovery unreachable. Should use tenant custom domain name (e.g., `contoso`).

### Deployment Gaps

5. **main.bicep doesn't pass Entra params** — Entra environment variables not declared in `main.bicep` to container app module.
   - Impact: UAT deployment omits Entra config unless CI/CD pipeline compensates
   - Note: CI/CD may be working around this via direct Azure CLI calls

6. **No login path in UAT if Entra broken** — `ALLOW_LOCAL_AUTH=false` with broken OAuth = completely locked out.
   - Impact: Testing Entra fixes requires temporary `ALLOW_LOCAL_AUTH=true` or Entra working end-to-end

## Architectural Validation

✅ **Confirmed:** Entra is correctly scoped as identity provider only. Code implements minimal viable integration (OIDC → find-or-create → own session token). No over-engineering detected.
