## Root Cause Analysis

The admin Room Graph tab relied on a separate zone-data API fetch (`GET /admin/api/zones/:slug`) to populate the room list. For **procedural zones** (which have no `zoneSlug` property), this fetch always returned null. The `roomOccupancy` useMemo would short-circuit when `zoneData` was null, returning an empty occupancy map and silently hiding all creature display.

Jarlaxle's earlier fix (a82cf3d) addressed three surface symptoms but did not resolve the root cause:
- Fire-and-forget `loadRoom` call  
- Invalid room ID validation logic  
- Hardcoded zone name fallback  

## Solution Implemented

Modified `getZoneDetail()` endpoint to include `roomGraphRooms[]` — a live room graph structure containing room id, name, and type for all rooms. The frontend now uses this authoritative list as a fallback when zone data is unavailable.

**Why this works:**
- Server already has the room graph; no need for a second client-side fetch  
- Fixes procedural zones AND any scenario where zone API fetch fails  
- Room graph is the source of truth for creature placement (spawn validates against it)  
- Ensures display consistency with actual spawn capability
