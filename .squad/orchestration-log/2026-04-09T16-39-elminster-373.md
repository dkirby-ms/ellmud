## Summary

Researched requirement to gate admin panel access behind per-user roles. Found that `player_identities.role` column already exists with valid roles defined in codebase. Gap identified: enforcement — auth middleware and client currently use static `ADMIN_TOKEN` instead of user role validation.

## Work Performed

1. **Schema Analysis:** Confirmed `player_identities.role` column exists in `001_schema.sql`, defaults to `'player'`. Valid roles `['player', 'viewer', 'moderator', 'admin']` already defined.

2. **Codebase Survey:** Identified:
   - Admin CRUD exists: role can be set via `user-routes.ts`
   - Admin middleware (`adminAuth`) checks static `ADMIN_TOKEN` env var only
   - `/auth/me` endpoint returns `{ playerId, username }` — **missing role**
   - Client stores admin token in `localStorage` separately from session
   - No route-level role gating mechanism

3. **Design Proposal:** Filed comprehensive design proposal including:
   - Shared types layer (`UserRole` enum + `ROLE_HIERARCHY`)
   - Auth endpoint extension: expose role in `/auth/me`
   - Server middleware refactor: role-based checks with ADMIN_TOKEN fallback
   - Client state: add `role` to app state
   - Admin layout: gate by role instead of separate token
   - Migration path ensuring backward compatibility
   - Implementation checklist + file reference table
