## Work Summary

Implemented content management tooling for cleaning up stale exits in `zone_exits` table that reference rooms or zones no longer in the game.

### Implementation

- **Interface Methods:** `findOrphanedExits()` and `removeOrphanedExits()` added to `ZoneRepository` contract
- **SQL Implementation:** Full logic in `PgZoneRepository.ts` with four orphan detection categories:
  1. `from_room_slug` references missing rooms
  2. `to_room_slug` references missing rooms (intra-zone only)
  3. `target_zone_slug` references missing zones (cross-zone)
  4. `target_room_slug` references missing target rooms (cross-zone)
- **In-Memory Fallback:** Parallel implementation in `InMemoryZoneRepository` for testing
- **Admin API:** `/admin/api/zones/cleanup/orphaned-exits`
  - `GET`: Dry-run preview of exits to be deleted
  - `POST`: Perform actual deletion with audit logging
- **Route Registration:** Cleanup routes registered *before* `/:slug` wildcard to prevent Express parameter collision
