### Key Decisions

1. **Three-layer architecture:** Parser (text→command) → Handlers (pure functions) → Delivery (Colyseus send)
   - Handlers are stateless and unit-testable without Colyseus dependencies
   - Extensibility: New command = handler file + registry line (critical for Issue #6-7 combat system)

2. **CommandContext + CommandResult types:** Stable public API for all future handlers
   - Context: player state, current room, resolver function, occupants list
   - Result: narration entries with type tags (attack, defense, flavor, etc.) for future LLM enrichment

3. **LLM-ready narration structure:** Each narration entry has `{type, text}` — when LLM lands, handlers return template keys and delivery layer enriches them
   - No handler changes needed when LLM integrates (Issue #9 compatibility built-in)

4. **Movement validation:** Room exits validated against RoomGraph contract from Jarlaxle's Issue #5
   - Direction aliases: w/west, e/east, n/north, s/south, u/up, d/down
   - Blocked exit returns specific narration ("You can't go that way")

5. **Inventory carrying limit:** 20 items per player (can be tuned)
   - Take/drop handlers enforce this silently (no spam)

### Cross-Team Impact

- **Jarlaxle (Issue #5):** Your `RoomGraph` interface is the navigation contract. Movement handler validates exits against your room definitions. Test graph is disposable — production graph will be generated by your generator.

- **Minsc (Tests):** Command tests use factories to build context. Integration tests verify Colyseus dispatch. No shared test infrastructure — tests are independent per agent.

- **Issue #6-7 (Combat):** Combat handlers will follow identical pattern. Strike/dodge/flee will slot into handler registry without modifying parser or delivery layer.
