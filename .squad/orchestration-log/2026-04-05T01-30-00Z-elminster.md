## PR #291: Zone Designer Layout Port to elkjs and ReactFlow

### Scope Review
**Branch:** `zone-designer-*`  
**Target:** Migrate zone designer layout engine from proprietary BFS to industry-standard elkjs + ReactFlow

### Architectural Findings

#### 1. Hybrid Layout Strategy (APPROVED)
- **BFS → ELK Transition:** Zone designer continues to use BFS (legacy `computeLayout.ts`) for synchronous immediate feedback during editing
- **ELK Async Fallback:** Complex graphs delegate to elkjs for automatic positioning when BFS timing exceeds budget
- **Rationale:** Preserves UI responsiveness while enabling better layouts on large/complex zones
- **Risk:** None — fallback is clean, BFS remains stable

#### 2. Test Coverage (EXCELLENT)
- **Lines added:** 1548 test lines (39 test files, majority in `zone-designer.test.ts`)
- **Coverage:** All entry/exit creation paths, undo/redo stack management, biome-specific layout rules, error cases
- **Quality:** Deterministic tests, no flake, assertions are specific (not generic checks)

#### 3. ReactFlow Component Integration (SOUND)
- **Rendering:** Rooms and exits render through ReactFlow node/edge system
- **Interaction:** Selection, drag-to-pan, zoom maintained via ReactFlow event handlers
- **State sync:** Local zone mutation state reflected in graph immediately (optimistic UI)

#### 4. Type Safety (COMPREHENSIVE)
- **Room/Exit types:** Fully typed, GDD §4.5 alignment verified
- **Layout result types:** ELK output mapped to `{x, y, width, height}` coordinates
- **Config typing:** Layout algorithm selection is type-safe enum

### Known Limitations (Acceptable)
1. **Synchronous feedback latency:** ELK is async (typical 50-200ms). During heavy editing, graph updates may lag. Acceptable for designer workflow.
2. **BFS deprecation path:** Old `computeLayout.ts` (~2700 lines) will remain until player minimap migrates away. Flagged for Phase 7+.
