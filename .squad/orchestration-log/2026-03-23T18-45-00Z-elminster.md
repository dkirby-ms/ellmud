### Issue Grouping Rationale

**Why not 27 separate issues?**
- All 8 detail page Save buttons have identical requirements (call PUT endpoint, handle errors, show loading)
- Bulk actions cluster into 1 feature (not 3 separate issues)
- Pagination Previous/Next is 1 feature (not 2)
- Result: 27 issues → confusing dependency graph, unmaintainable backlog

**Why group by entity type?**
- Admin pages follow consistent CRUD pattern (List → Detail → Save)
- Grouping by entity (Creatures, Items, Biomes, etc.) makes this pattern explicit
- Engineers can build once per entity and reuse pattern

**Why is #139 P1 blocker?**
- All detail pages depend on GET/PUT endpoints for their respective entity types
- Prevents wasted effort on UI wiring without backend infrastructure
- Must exist before any detail page wiring can be tested
