## Spawn Context
User requested thorough review of BFS engine while making grid spacing changes. The layout engine has accumulated technical debt through many iterations and needed architectural assessment before further modifications.

## Critical Findings

### P0: Performance Bottleneck
- **O(n⁴) scoring algorithm** in position evaluation
  - Nested quadruple loops over grid positions
  - Evaluates every position against every other position for every candidate placement
  - Scales explosively with density; becomes intractable in zones with >20 rooms
- **Mitigation:** Implement incremental scoring - pre-compute distance maps or use spatial partitioning

### P1: Logic Defects & Code Quality
- **Infinite loop risk** in `findNearestUnoccupied()` 
  - No iteration limit; can deadlock if all positions are occupied
  - Should have escape condition or throw after N attempts
- **23+ magic numbers** scattered throughout
  - `8, 16, 5, 20, 0.5, 1.5, 3, 4` — no semantic meaning
  - Recommend: Extract as named constants (GRID_BUFFER, COLLISION_THRESHOLD, etc.)
- **DRY violations** — diamond search boilerplate copy-pasted 3+ times
  - Extract directional iteration into helper function
- **GRID_STEP = 1** — confirmed as no-op
  - Set to 1, multiplied by 1, never changes behavior
  - Appears to be vestigial from earlier design phase

### P2: Refactoring Opportunities
- **Helper extraction** — reduce function length and improve readability
  - Candidate functions: `searchDiamond()`, `scorePosition()`, `evaluateCollision()`
- **Type safety** — several untyped object accesses
- **Testing gaps** — limited unit test coverage for edge cases

## Recommendations (Priority Order)

1. **Immediate (P0):** Fix O(n⁴) scoring
   - Impact: Essential for scaling
   - Effort: Medium (1-2 days)
   - Approach: Incremental scoring with spatial index

2. **High Priority (P1):** Extract magic numbers, fix infinite loop risk
   - Impact: Robustness and maintainability
   - Effort: High (2-3 days)
   - Approach: Systematic refactor with test suite

3. **Medium Priority (P2):** Extract helpers, improve DRY
   - Impact: Code clarity
   - Effort: Medium (1-2 days)
   - Approach: Modular decomposition
