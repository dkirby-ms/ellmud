## Investigation Summary

Traced the complete flow from auth system through player onJoin to database persistence:

### Auth System (✓ Working Correctly)
- `LocalAuthStrategy.onAuth()` correctly sets `client.auth.playerId` with a valid UUID
- Auth flow is sound; credentials validated, JWT/token handling correct
- Player identity is established at authentication time

### Identity Handoff (✗ BROKEN)
**Root Cause:** ShardRoom.onJoin (line 252) and RefugeRoom.onJoin (line 91) read `options['playerId']` instead of `client.auth.playerId`

In Colyseus 0.17:
- `onAuth()` return value is set as `client.auth`, NOT merged into `options`
- Client sends `{ token }` in options — no `playerId` field
- Code falls back to `client.sessionId` (9-char nanoid)

### Impact Chain
1. **SessionId is NOT a UUID:** All game tables expect `player_id UUID`
2. **FK Violation:** `client.sessionId` doesn't exist in `players` table
3. **Silent Failures:** Postgres inserts fail silently on FK constraint
4. **No Persistence:** Each reconnection generates a new sessionId → orphaned data

### Database State
- `players` table: Contains valid UUIDs from registration
- `player_skills` table: Empty rows or rows keyed by invalid sessionIds
- **Why:** All writes use wrong foreign key (sessionId instead of playerId)

## Root Cause Details

**File:** `packages/server/src/rooms/ShardRoom.ts:252`
```typescript
// CURRENT (BROKEN):
const playerId = options['playerId'] || client.sessionId;

// REQUIRED:
const authData = client.auth as { playerId?: string; username?: string } | undefined;
const playerId = authData?.playerId || (options['playerId'] as string) || client.sessionId;
```

Same issue in `packages/server/src/rooms/RefugeRoom.ts:91`
