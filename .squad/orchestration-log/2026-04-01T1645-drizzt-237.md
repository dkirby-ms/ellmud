## Summary

- **PR #258** — Corpse/loot-on-death system complete

  - Separate from TraceSystem (maintains single responsibility: traces = visual only, corpses = lootable containers)
  - Supports inventory storage with weight/item limits
  - TTL-based decay (configurable per ServerConfig)
- **33 new tests** — Corpse creation, loot command, TTL expiry, soulbound filtering
- **Death Handler Refactor:**

  - Equipment-to-corpse conversion deferred (requires async loadout resolution)
- **Parser/Command Changes:**
  - `loot` verb added to command registry
  - Syntax: `loot <corpse-id>` or `loot corpse`
  - Returns items to player inventory with weight checks
- **Configuration:**
  - `corpseTTLSeconds` added to ServerConfig (default 600)
  - Environment variable: `CORPSE_TTL_SECONDS`
- **UI Changes:**
  - `look` command now displays corpses with item counts (e.g., "A corpse (8 items)")
  - Corpse objects visible to all players in zone (non-soulbound transparency)

## Architecture Decisions

1. **In-Memory Storage** — Appropriate since room items are already ephemeral (destroyed on zone collapse)
2. **Separate System** — Traces and corpses have different concerns; keeping separate maintains clarity
3. **Soulbound Check** — Leverages existing `ItemDefinition.soulbound` field from item registry
4. **TTL-Based Cleanup** — Prevents unbounded corpse accumulation; configurable for balance tuning
