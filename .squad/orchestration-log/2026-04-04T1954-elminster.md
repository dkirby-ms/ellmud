## Decision Summary

**Status:** Approved for Architecture Phase

**Direction:** elkjs + ReactFlow is the long-term solution for zone designer rendering.

**Rationale:**
- **ELK.js:** Industrial-grade crossing minimization (Sugiyama algorithm), MUD-aware constraints (compass directions as port-side assignments), direction layers (Z-axis support)
- **ReactFlow:** Built-in pan/zoom/minimap, component-based rendering, eliminates 3600+ lines of hand-rolled SVG code
- **Phased approach:** 6 independent phases allow parallel work, early feedback, and risk mitigation

**Timeline:** 6–8 weeks (Phase 0: 2–3 days, Phases 1–6: incrementally)

**Implementation Ownership:**
- **Phases 0–1:** Regis (Frontend Dev) + Elminster (Arch review)
- **Phase 2:** Regis + Elminster (ELK integration)
- **Phases 3–6:** Regis (ReactFlow, polish, cleanup)

---

## Key Decisions Locked In

1. **No big-bang rewrite:** Phases are independent; existing designer remains functional during migration
2. **Layout + Rendering split:** ELK handles crossing minimization; ReactFlow handles interaction/pan/zoom
3. **MUD constraints encoded:** Compass directions map to ELK port-sides; multi-floor (Z-axis) uses layer constraints
4. **Visual improvements first:** Phase 1 (curves, colors, shapes) delivers value before Phase 2 (ELK swap)
